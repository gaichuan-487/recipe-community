# 食光记 · 美食菜谱分享社区

一个可以直接运行、用于演示和课程作业的美食菜谱分享社区。用户可以发布带步骤配图的菜谱，按食材与风味标签浏览，点赞、收藏、留言；管理员负责菜谱审核并查看社区数据统计。

## 功能一览

### 用户端

- **菜谱发布**：标题、简介、分类、耗时、份量、难度、最多 6 个标签，食材清单，多步骤文字 + 步骤配图，作者小贴士。食材用量可以留空，留空时只显示食材名称；步骤配图按整份菜谱计，至少一张即可，不要求每步都配图。标签除了预设的常见食材与风味，还可以自己输入食材名；审核通过后会自动出现在首页食材架和筛选列表中。
- **图片上传**：封面与步骤图支持 JPG / PNG / WebP / GIF，单张不超过 8MB。
- **发现与筛选**：按关键词、分类、食材/风味标签筛选，支持排序。
- **菜谱详情**：食材用量、分步做法、步骤大图查看、点赞、收藏、评论、复制分享链接。
- **热门排行**：按点赞、收藏、评论、浏览与新鲜度综合计算热度。
- **个人中心**：我的作品（已发布 / 审核中 / 未通过）、我的收藏、收到的数据统计；支持编辑、删除自己的菜谱，修改后重新进入审核。
- **账号体系**：注册、登录、退出；登录状态保持 7 天。

### 管理端

- **菜谱审核**：待审核队列、详情预览、通过 / 驳回（驳回需填写至少 5 字的修改建议，作者可在个人中心看到原因）。
- **全部菜谱**：按状态筛选、搜索、查看与处理。
- **用户管理**：按状态筛选与用户名/昵称搜索，查看作品与留言数量；可封禁 / 解封账号。封禁只暂停登录与写操作，已发布的菜谱和评论继续公开展示；封禁原因选填、仅后台可见。
- **数据统计**：用户、菜谱、待审核、评论等总量，近 7 日发布趋势图，分类与标签分布，热门菜谱榜，最近待审核列表。图表带悬浮提示和无障碍数据表。

### 体验细节

- 响应式布局，适配桌面与手机。
- 表单校验、发布检查清单、上传进度与操作提示。
- 键盘可操作的弹窗（Esc 关闭、焦点循环）、跳转到主内容链接、`prefers-reduced-motion` 与高对比度支持。
- 所有图标与插画均为本地资源，无外部字体或 CDN 依赖。

## 快速开始

环境要求：**Node.js 18 或更高版本**。

```bash
cd recipe-community
npm install
npm start
```

浏览器打开 <http://localhost:3000>。默认提供的是 **Vue 3 版前端**，构建产物由 `frontend/` 生成并发布到 `public/`。

开发时可使用自动重启后端：

```bash
npm run dev
```

### Vue 前端开发

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173，接口自动代理到 3000
npm run publish    # 构建并发布到 public/，之后 npm start 即提供最新版本
```

旧版原生前端已完整备份在 `legacy-frontend/`，`public/` 只保留 Vue 构建产物、图片与上传目录。

## 项目结构

```
recipe-community/
├─ server.js              # Express 服务端、API、鉴权、审核与封禁逻辑
├─ lib/
│  ├─ store.js            # JSON 数据读写（原子写入）
│  └─ seed.js             # 首次启动的演示数据
├─ frontend/              # Vue 3 前端源码（Vite + vue-router + Pinia）
│  ├─ src/                # 页面、组件、状态与 API 封装
│  └─ scripts/publish.mjs # 构建产物发布到 public/
├─ public/                # 后端静态目录：Vue 构建产物 + 共享资源
│  ├─ index.html          # Vue 入口（由 npm run publish 生成）
│  ├─ assets/             # 带哈希的 JS / CSS（同上）
│  ├─ images/             # 演示图片
│  └─ uploads/            # 用户上传图片
├─ legacy-frontend/       # 旧版原生前端备份（index.html + css/ + js/）
├─ data/
│  ├─ db.json             # 运行数据（首次启动自动生成）
│  └─ .secret             # 令牌签名密钥（自动生成）
├─ package.json
└─ README.md
```

## 数据与存储说明

- 项目使用 **JSON 文件持久化**，数据保存在 `data/db.json`；写入采用临时文件 + 重命名的原子方式，避免写坏文件。
- 密码使用 Node.js `scrypt` 加盐哈希存储，不保存明文。
- 登录令牌为 HMAC-SHA256 签名、有效期 7 天的无状态 Token。
- 上传图片保存在 `public/uploads/`，文件名随机生成。

### 重置演示数据

1. 停止服务。
2. 删除 `data/db.json`（保留 `data/.secret`，也可以一起删除重新生成）。
3. 清空 `public/uploads/` 中的测试图片（保留 `.gitkeep`）。
4. 重新执行 `npm start`，系统会按 `lib/seed.js` 自动生成演示账号、菜谱、评论与待审核数据。

## 适用场景与限制

本项目面向演示、课程作业与小型内网使用：

- JSON 文件存储适合单进程运行，**不适合**多实例部署或高并发生产环境。
- 未接入邮件、短信、第三方登录与对象存储。
- 若用于公网生产环境，建议替换为数据库、对象存储，并补充 HTTPS、限流、内容安全与备份策略。

## 实现要点

- **审核状态流**：`pending → approved / rejected`；用户新建或编辑菜谱进入 `pending`，管理员创建的内容自动通过；待审核内容仅作者本人和管理员可见。
- **热门算法**：`(点赞 × 3 + 收藏 × 5 + 评论 × 4 + 浏览 ÷ 120) × 新鲜度衰减`，避免只看总量的“老帖霸榜”。
- **权限控制**：公开只读接口无需登录；发布、上传、互动需要登录；审核与统计仅管理员可访问。
